# Etch primitives (building blocks for any layout)

Every layout the builder makes is composed from these. For each one: what it is, how it is stored (Path A, block markup in `post_content`), how it is made through the Public API (Path B, `window.etch`), the rules that matter, the docs page, and staging status.
Read `guardrails.md` first. Docs: `https://docs.etchwp.com` + path, re-read 2026-10-07 (Etch 1.6.8). Stored forms: `fixtures/catalogue.md` (real saved markup); never hand-invent a stored form that is not there or in a passing round-trip.
Status: **proven** = round-tripped from generated markup (`confirmed-on-staging.md`); **seen** = in saved staging markup, not yet generated by us; **docs only** = not seen on staging.

## Section and Container
- **What:** `section[data-etch-element=section]` > `div[data-etch-element=container]`. The section handles semantics, gutter and vertical rhythm; the container sets `max-width: var(--content-width)`, centres itself (`align-self: center`), and is `display: flex; flex-direction: column` with gap support. (D `/elements/section`, `/elements/container`)
- **Stored:** both carry their built-in style IDs `etch-section-style` / `etch-container-style` plus `aria-labelledby` to the heading id (`catalogue.md`, Section skeleton).
- **Rules:** every section starts with a heading (h1 in the first, h2 after); no heading → a div. Several containers in one section are fine; full-bleed pieces sit outside the container. Change width with `--content-width`. Grid layouts go on a child of the container (or on the container through its class), not by replacing it.
- **Layout recipe:** split = container > `div.x__grid` with two children; card grid = container > section head + `ul` grid (loop the `li`).

## Element and Dynamic element
- **Element:** any tag (`etch/element`, `tag`, `attributes`, optional `styles`, `script`). Tags seen on staging: main, section, div, p, h1-h3, span, a, nav, ul/ol/li, article, aside, header, footer, figure/figcaption, blockquote/cite, button, form, fieldset/legend, label, input, textarea, dialog, dl/dt/dd, svg/g/path (`catalogue.md`).
- **Div** has no default styling; flex alignment and gap need `display: flex` (D `/elements/div`).
- **Heading** defaults to h2; set the level by semantics, size by CSS (D `/elements/heading`).
- **Dynamic element** `<etch:element tag={props.headingLevel}>`: swap a tag from a prop or field without conditions, e.g. one Section Intro component used as h1 in a hero and h2 elsewhere. Works anywhere but is only in the Elements Bar in component mode (D `/elements/element`).
- **API:** `etch.blocks.create({type: "etch/element", version: 1, tag, attributes, children, script})`; creating under a parent that cannot contain the block (text block, void element) throws `WRONG_BLOCK_TYPE` (D `/public-api/blocks`).
- **Empty elements** show at min 35px in the builder only; override per element with `--empty-element-size`, never globally (D `/elements/empty-elements`).

## Text
- `etch/text` (self-closing, `content`) inside an element; text never sits bare. Default `p`, can morph to span, li etc. A single text element is never rich text (several paragraphs): use the HTML element (D `/elements/text`).

## Dynamic image
- `<etch:img>` / `etch/dynamic-image` with `mediaId` (a WP media ID or an expression such as `{item.image.id}`). Renders `alt`, `src`, `srcset`, `sizes`; alt comes from the media library unless overridden; `maximumSize` picks a size; `useSrcSet` false turns srcset off. Other attributes pass through to the `img` (D `/elements/dynamic-image`).
- **Stored:** `tag:"img"`, `attributes{mediaId,useSrcSet,loading,alt}`, values as strings (`catalogue.md`).
- **Rules:** never a plain `img`; `loading="eager"` only above the fold; set `aspect-ratio` + `object-fit` on the image class when the box must hold its shape. In a component, pass the ID through a media or text prop.

## SVG
- `<etch:svg src="...">` takes a media-library file or any URL; `stripColors="true"` turns hard-coded colours into `currentColor`. With a component Image prop: `src="{props.icon}"` (D `/elements/svg`). API: `setAttribute(id, "src", ...)`, `setAttribute(id, "stripColors", "true")` (D `/public-api/blocks`).
- Staging has only pasted `svg`/`path` elements (decorative, `aria-hidden="true"`). The first generated `etch:svg` needs a round-trip.

## HTML (raw)
- `<etch:html content={...} />`, self-closing, for rich text from data. Parent must be a `div` (rich text brings its own p/h2/ul). `unsafe="false"` (default) sanitises to post-allowed HTML; `unsafe="true"` is disabled on staging and stays off (D `/elements/html`, S).

## Components
- **Instance stored:** `etch/component` with `ref` (wp_block ID) and `attributes` = prop values; booleans as `"{true}"`; object props as JSON strings (`catalogue.md`). API: prop schema is closed, an undeclared prop throws `INVALID_ARGUMENT` (D `/public-api/blocks`).
- **Props:** text, boolean, select (`label : value`), media, loop, object, class, group, repeater, condition (D `/components/props/*`). Map with `{props.key}`.
- **Variations:** one component, props drive it: boolean + `{#if}`, select + data attribute, inline tokens `style="--card-bg: {props.cardBg}"`. Never duplicate a component per variant (D `/components/creating-component-variations`).
- **Scope:** a component sees only `this`, `site`, `url` and its props; pass loop or template data in as prop values (`{item.title}`, `{item.image.id}`, `{item.permalink.relative}`) (D `/components/using-a-component-dynamic`).
- **Reuse first:** existing refs on staging: 143 callout band (tones ink, butter, blue), 176 page hero, 457 newsletter band, header 22, footer 28 (`fixtures/README.md`).

## Slots
- Define `{@slot name}` in the component; fill `{#slot name}...{/slot}` on the instance. Stored as `etch/slot-placeholder` (definition) and `etch/slot-content` (instance). `slots.name.empty` is true when the slot has no content: use it for fallbacks and to drop empty wrappers (D `/components/slots`).
- Use slots for free-form content (an FAQ answer, a card body). Slot content cannot read a loop that runs inside the component.

## Loops
- Loop element is a ghost (no DOM output) (D `/elements/loop`). Sources: WP Query, JSON, WP Terms, WP Users, Main Query on archive templates (D `/loops/basic-loops`, `/loops/main-query`).
- Syntax `{#loop name as item}` or `{#loop name($count: 3) as item, index}`. Stored `etch/loop` with `loopId` (key in `etch_loops`) and `itemId` (`catalogue.md`).
- Loop the `li`, not the card inside it. Reuse one saved loop with args (`$count ?? 10`, first default wins); quote string args. Nested loops: pass the parent id (`posts($cat: category.id)`) and use a different item name, or the inner loop hides the outer (D `/loops/loop-arguments`, `/loops/nested-loops`).
- No results: a second loop on `.length().equal(0,[1],[])` (D `/loops/basic-loops`).

## Conditions
- Condition element is a ghost. `{#if ...}{/if}` with `!`, `&&`, `||`, parentheses, `==`, `!=`, `===` (default strict), `!==`; quotes only around strings. Inside attributes use comparison modifiers. Stored `etch/condition` with `condition{leftHand,operator,rightHand}` + `conditionString` (D `/elements/condition`, `/conditional-logic/*`; `catalogue.md`). `{#else}`: unconfirmed, do not use.

## Block scripts
- Any block may carry `script: {code}`; it is enqueued in `<head>` as a deferred `type="module"` with no link to the element, so target by selector and scope to the block's class (D `/public-api/blocks`). Stored base64 in `script.code` with a 7-character `id` (`catalogue.md`). Honour `prefers-reduced-motion`; no globals, no inline handlers.

## Templates
- Index template = catch-all; single, archive, author, search, 404 recommended. Shape: header component + `main` with `{@post-content}` + footer component; single posts put `{@post-content}` in `article`. Templates author to WordPress FSE (D `/templates/intro-to-templates`, `/templates/post-content-slot`).

## Native components
- Listed (D `/components-native/overview`): Accordion, Advanced Nav, Alert Banner, Basic Nav, Before After, Carousel, Copy To Clipboard, Countdown, Dev Note, Dialog, Drawer, Gallery, Greeter, Hotspot, Icon, Menu Bar, Lightbox, Logo Carousel, Map, Off Canvas, Read More, Reading Progress, Scroll Snap, Search, Skip Link, Slide Menu, Star Rating, Switch, Table Of Contents, Table, Tabs, Tooltip. Only Basic Nav (+ Burger) and Off Canvas had full setup docs when the plan was written; treat the rest as unproven until tested on a test page. Our pages use custom components and native HTML (`details`/`summary`, `dialog`) instead.

## Composing a layout (how the builder uses this file)
1. Each spec section → one Section > Container (or the landmark the spec names).
2. Inside: section head (kicker, heading, lede) then the body pattern: split, grid (`ul` + loop or static `li`), stack, or a component instance.
3. Repeated block 2+ times → component with props; free-form inner content → slot; data → loop feeding component props.
4. Styles: one class per element that needs styling, nested BEM in its attached CSS, ACSS tokens inside (`acss-expert`), responsive per `responsive.md`.
5. New construct set (signature) → round-trip gate before it counts as proven; then update the status table above.
